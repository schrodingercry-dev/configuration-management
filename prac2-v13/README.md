# Практическая работа №2 — вариант 13

Этап 1: минимальный прототип инструмента визуализации графа зависимостей
пакетов Ubuntu (apt).

На этом этапе программа только принимает, проверяет и выводит параметры.
Получение зависимостей и построение графа относятся к следующим этапам и пока
не реализованы.

## Параметры

- `--package` — имя анализируемого пакета;
- `--repository` — URL репозитория или путь к файлу тестового репозитория;
- `--test-mode` — использовать файл тестового репозитория вместо URL;
- `--version` — версия пакета;
- `--ascii-tree` — включить режим ASCII-дерева;
- `--max-depth` — максимальная глубина анализа, целое число от 0.

## Запуск

Из папки `prac2-v13`:

```bash
python3 -m src.main \
  --package curl \
  --repository https://archive.ubuntu.com/ubuntu \
  --version 8.5.0-2ubuntu10.6 \
  --ascii-tree \
  --max-depth 3
```

Результат:

```text
package: curl
repository: https://archive.ubuntu.com/ubuntu
test_mode: False
version: 8.5.0-2ubuntu10.6
ascii_tree: True
max_depth: 3
```

Для тестового репозитория сначала создайте обычный файл, затем запустите:

```bash
python3 -m src.main \
  --package a \
  --repository examples/test_repository.txt \
  --test-mode \
  --version 1.0 \
  --max-depth 2
```

Содержимое файла пока не разбирается: это будет сделано на следующем этапе.


## Обработка ошибок

Программа завершает работу с кодом `2` и понятным сообщением, если:

- пропущен обязательный параметр;
- имя пакета имеет неверный формат;
- версия пуста, содержит пробелы или недопустимые символы;
- без `--test-mode` указан некорректный HTTP/HTTPS URL;
- с `--test-mode` указан отсутствующий файл;
- максимальная глубина не является целым неотрицательным числом;
- передана неизвестная опция или значение после логического флага.

Справка по параметрам:

```bash
python3 -m src.main --help
```

## Что сказать на защите

1. `argparse` разбирает опции командной строки и сам проверяет обязательные
   параметры и неизвестные опции.
2. Для имени, версии и глубины используются отдельные функции валидации.
3. В обычном режиме `--repository` должен быть HTTP/HTTPS URL, а в тестовом
   режиме — путём к существующему файлу.
4. `--test-mode` и `--ascii-tree` — логические флаги: их наличие означает
   `True`, отсутствие — `False`.
5. Глубина `0` допустима и означает, что анализ ограничен исходным пакетом.
