## Сборка и запуск

Проект написан на Python 3. Сборка и установка дополнительных библиотек не требуются, поскольку используются только модули стандартной библиотеки Python.

Все команды необходимо выполнять из корневой папки практической работы `prac1-v13`.

### 1. Обычный запуск эмулятора

```bash
bash run.sh
```

Запускает эмулятор командной оболочки в интерактивном режиме.

- `bash` — интерпретатор команд, выполняющий Bash-скрипты.
- `run.sh` — скрипт запуска программы.

После запуска пользователь может вводить команды `ls`, `cd`, `conf-dump` и `exit`.

На текущем этапе `ls` и `cd` реализованы как заглушки: они выводят название команды и переданные аргументы.

### 2. Запуск с виртуальной файловой системой и стартовым скриптом

```bash
bash run.sh --vfs vfs/deep_tree.json --script scripts/startup.txt
```

Запускает эмулятор с указанной виртуальной файловой системой (VFS) и автоматически выполняет команды из стартового скрипта.

Параметры:

- `--vfs` — указывает путь к JSON-файлу виртуальной файловой системы.
- `vfs/deep_tree.json` — пример VFS с вложенными каталогами.
- `--script` — указывает путь к стартовому скрипту.
- `scripts/startup.txt` — текстовый файл с командами для автоматического выполнения.

При запуске программа загружает и проверяет VFS, затем последовательно выполняет команды из стартового скрипта.

Если в скрипте встречается ошибочная команда, эмулятор сообщает об ошибке и продолжает выполнение следующих команд.

После завершения стартового скрипта программа переходит в интерактивный режим.

### 3. Запуск автоматических тестов Python

```bash
python3 -m unittest discover -s tests -v
```

Запускает автоматические тесты проекта с помощью стандартного модуля Python `unittest`.

Параметры:

- `python3` — интерпретатор Python 3.
- `-m unittest` — запуск модуля тестирования.
- `discover` — автоматический поиск тестов.
- `-s tests` — поиск тестов в папке `tests`.
- `-v` — подробный вывод результатов проверки.

В проекте реализовано 8 автоматических тестов. Они проверяют обработку команд, аргументов, переменных окружения, конфигурации, стартовых скриптов и виртуальной файловой системы.

При успешном выполнении всех тестов выводится:

```text
Ran 8 tests

OK
```

### 4. Тестирование первого этапа

```bash
bash scripts/test_stage1.sh
```

Запускает Bash-скрипт для проверки первого этапа практической работы.

Первый этап включает:

- запуск интерактивной командной оболочки;
- обработку введённых команд;
- разбор аргументов;
- раскрытие переменных окружения;
- работу заглушек `ls` и `cd`;
- завершение работы командой `exit`;
- обработку ошибочного ввода.

### 5. Тестирование второго этапа

```bash
bash scripts/test_stage2.sh
```

Запускает Bash-скрипт для проверки второго этапа практической работы.

Второй этап включает:

- обработку параметров командной строки `--vfs` и `--script`;
- выполнение команд из стартового скрипта;
- продолжение выполнения скрипта после ошибочной команды;
- вывод конфигурации с помощью `conf-dump`.

### 6. Тестирование третьего этапа

```bash
bash scripts/test_stage3.sh
```

Запускает Bash-скрипт для проверки третьего этапа практической работы.

Третий этап включает:

- загрузку виртуальной файловой системы из JSON;
- проверку структуры файлов и каталогов;
- проверку содержимого файлов в кодировке Base64;
- обработку ошибок при загрузке VFS;
- проверку файловых систем с различной структурой и глубиной вложенности.

Для проверки используются JSON-файлы из папки `vfs`.

### 7. Дополнительные примеры проверки VFS

Загрузка корректной виртуальной файловой системы:

```bash
bash run.sh --vfs vfs/deep_tree.json
```

При успешной загрузке появляется приглашение:

```text
deep_tree>
```

Загрузка VFS с некорректным содержимым Base64:

```bash
bash run.sh --vfs vfs/invalid.json
```

Результат:

```text
Startup error: Invalid base64 file content
```

Попытка загрузить несуществующий файл:

```bash
bash run.sh --vfs vfs/not_found.json
```

Программа сообщает об ошибке отсутствующего файла.

### 8. Завершение работы

Для корректного завершения интерактивного режима используется команда:

```text
exit
```

Эмулятор завершает работу и возвращает управление обычному терминалу.
